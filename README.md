# Floraqua

Floraqua — desktop-приложение на Flutter для ведения домашнего сада. Оно хранит карточки растений, помогает планировать полив, показывает сезонные ориентиры и может распознавать растение по фотографии через Google Gemini.

> **Важно:** Floraqua не содержит общего API-ключа разработчика. Каждый пользователь вводит собственный Gemini API-ключ, который хранится локально на его устройстве.

## Возможности

- добавление растения по фото из галереи или с камеры;
- распознавание растения и получение базовых рекомендаций через Gemini;
- ручное имя, заметки, размер горшка, расположение и наличие дренажа;
- сеточный и списочный режимы отображения;
- поиск и фильтры «Все», «К поливу», «Здоровы»;
- кольцо с числом дней до полива;
- отметка фактического полива и история до 100 последних событий;
- редактирование частоты полива и даты последнего полива;
- сезонная корректировка расписания для Северного полушария;
- локальные системные уведомления;
- экспорт и импорт сада вместе с фотографиями в `.zip`;
- экспорт календаря полива в `.ics`;
- русский и английский интерфейс;
- светлая, тёмная и системная тема;
- локальное хранение данных без обязательного облачного аккаунта.

Расписание полива является ориентиром. Перед поливом всегда проверяйте влажность грунта и состояние конкретного растения.

## Требования

- Flutter stable с поддержкой Dart SDK `>=3.4.0 <4.0.0`;
- Windows 10/11 для desktop-сборки;
- интернет при распознавании растения и повторной проверке по фото;
- личный ключ Google Gemini API для AI-функций.

Для работы без Gemini уже сохранённые растения, ручное редактирование, история полива, импорт/экспорт и календарь работают локально.

## Сборка Windows EXE

Release-сборка:

```powershell
flutter clean
flutter pub get
flutter gen-l10n
flutter build windows --release
```

После успешной сборки основной EXE находится здесь:

```text
build\windows\x64\runner\Release\plant_garden.exe
```

Запуск собранной версии из PowerShell:

```powershell
.\build\windows\x64\runner\Release\plant_garden.exe
```

Для передачи пользователю копируйте **всю папку**:

```text
build\windows\x64\runner\Release\
```

Нельзя передавать только один `.exe`: рядом с ним находятся DLL и папки с ресурсами Flutter.

Удобно упаковать Release-папку в ZIP:

```powershell
Compress-Archive `
  -Path .\build\windows\x64\runner\Release\* `
  -DestinationPath .\Floraqua-Windows-Release.zip `
  -Force
```

## Первый запуск и Gemini API-ключ

1. Запустите Floraqua.
2. Пройдите короткий onboarding или пропустите его.
3. Введите собственный ключ Gemini API.
4. Ключ будет сохранён в защищённом локальном хранилище устройства.
5. Добавьте растение по фотографии.

Ключ не нужно добавлять в GitHub, `.env`, `pubspec.yaml` или исходный код. Не публикуйте его в Issues, логах и скриншотах.

## Если Gemini недоступен в России или вашем регионе

Для добавления растения Floraqua отправляет фотографию и контекст ухода в Google Gemini. В некоторых регионах, включая возможные ограничения доступа из России, соединение с Gemini может не установиться даже при работающем общем интернете.

В этом случае приложение показывает понятное сообщение:

> Не удалось подключиться к Gemini. Проверьте интернет. Если вы находитесь в России или другой стране с ограничением доступа к сервису, включите VPN и повторите попытку.

Порядок действий:

1. включите VPN с маршрутизацией трафика приложения;
2. проверьте, что браузер на этом же компьютере открывает нужные сервисы Google;
3. повторите анализ фотографии;
4. если ошибка сохраняется, проверьте правильность Gemini API-ключа и квоту в Google AI Studio.

Сообщение не утверждает, что проблема обязательно вызвана блокировкой: причиной также могут быть DNS, TLS, прокси, временный сбой Google или неверный ключ.

## Где хранятся данные

Сад и фотографии хранятся в каталоге application support текущего пользователя. На Windows это обычно каталог внутри профиля пользователя, например:

```text
C:\Users\<имя>\AppData\Roaming\plant_garden\
```

Основные файлы:

```text
my_garden.json          основной файл сада
my_garden.json.backup   резервная копия предыдущего состояния
plant_images\           фотографии растений
```

Точный путь может зависеть от версии Windows и Flutter-платформы. Для переноса между компьютерами используйте встроенный экспорт сада в `.zip`, а не копируйте внутренние файлы вручную.

## Экспорт и импорт

- `.zip` содержит JSON сада и фотографии;
- импорт полностью заменяет текущий список растений;
- перед импортом текущий JSON резервируется;
- пути к фотографиям перепривязываются к локальному каталогу нового устройства;
- входной архив ограничивается по размеру, числу файлов и распакованному объёму;
- `.ics` содержит даты полива примерно на год вперёд и может быть открыт Google Calendar, Outlook или Apple Calendar.

После изменения сада экспорт календаря `.ics` нужно создать заново.

## Структура проекта

```text
lib/
  models/       модели растений и настроек
  screens/      экраны и координация пользовательских действий
  services/     PlantStore, Gemini, уведомления, Secure Storage
  widgets/      карточки, формы, тулбар, сводка и общие виджеты
  l10n/         ARB-файлы и сгенерированные локализации
test/           unit/widget/regression-тесты
windows/        Windows runner
.github/        GitHub Actions для analyze, test и Windows release build
```

Состояние сада централизовано в `PlantStore extends ChangeNotifier`; интерфейс подписывается через `ListenableBuilder`.

## GitHub Actions

Workflow находится в `.github/workflows/flutter.yml` и запускает:

1. `flutter pub get`;
2. генерацию локализаций;
3. `flutter analyze`;
4. `flutter test`;
5. `flutter build windows --release`.

Проверка запускается для push, pull request и вручную из вкладки **Actions**.

Версия Flutter в CI закреплена в workflow. Обновляйте её отдельным изменением и проверяйте совместимость зависимостей.
