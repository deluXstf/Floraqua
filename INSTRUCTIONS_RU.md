# Floraqua — как установить и проверить на Windows

Эта инструкция рассчитана на обычную Windows-машину, даже если вы раньше не собирали приложения Flutter.

## 1. Подготовить инструменты

1. Установите **Flutter stable** по официальной инструкции: [docs.flutter.dev/get-started/install/windows](https://docs.flutter.dev/get-started/install/windows).
2. Установите **Visual Studio 2022** (это именно Visual Studio, не только VS Code) и отметьте компонент **Desktop development with C++**.
3. Откройте PowerShell и проверьте установку:

   ```powershell
   flutter doctor -v
   ```

   Если команда `flutter` не найдена, добавьте папку `flutter\bin` в переменную `PATH`, закройте PowerShell и откройте заново. В выводе `flutter doctor -v` устраните предупреждения для Windows desktop и Visual Studio.

## 2. Распаковать проект и запустить проверки

1. Сохраните резервную копию старого проекта.
2. Распакуйте `Floraqua_updated.zip` в короткий путь без кириллицы, например `C:\Floraqua`. Архив намеренно не содержит временные каталоги `build` и `.dart_tool`: благодаря этому в новой папке не останется старый CMake-кэш с путём к прежней копии проекта.
3. Откройте PowerShell в папке, где лежит `pubspec.yaml`, и выполните команды по одной:

   ```powershell
   cd C:\Floraqua
   flutter pub get
   flutter analyze
   flutter test
   flutter run -d windows
   ```

   Первый `flutter pub get` скачает зависимости — это может занять несколько минут. Запуск приложения можно остановить сочетанием **Ctrl+C** в PowerShell.

### Если снова появится ошибка CMakeCache.txt

Она означает, что сборочная папка была создана в другом месте. Из корня проекта выполните:

```powershell
flutter clean
flutter pub get
flutter run -d windows
```

`flutter clean` удаляет только пересобираемые файлы из `build`, а не код, фотографии или сохранённый сад пользователя.

## 3. Проверить первый запуск и ключ Gemini

1. При первом запуске пройдите короткое вступление, затем введите **свой личный Gemini API-ключ**. Получить ключ можно в [Google AI Studio](https://aistudio.google.com/app/apikey).
2. Ключ сохраняется в системном защищённом хранилище Windows и не включён в архив, исходники или тесты. Не публикуйте его в чате, GitHub или скриншотах.
3. Нажмите добавление растения и выберите **«Выбрать из фотогалереи»** или **«Сделать фото сейчас»**. Разрешите доступ к фото/камере, если iPhone спросит, и убедитесь, что Gemini создал карточку. Для этого сценария нужны интернет и действительный ключ.
4. Если приложение уже запускалось раньше, onboarding намеренно пропускается. Для повторной проверки можно безопасно сбросить только данные Floraqua — см. раздел ниже.

### Как снова увидеть первый запуск

1. Закройте Floraqua.
2. Нажмите **Win + R**, вставьте `%APPDATA%\com.example\Floraqua` и нажмите **Enter**.
3. Если папка открылась, переименуйте её в `Floraqua_backup` — не удаляйте. В ней находятся сохранённый сад и локальные настройки, включая зашифрованное хранилище ключа и отметку о завершённом onboarding.
4. Запустите Floraqua снова. Приложение создаст чистые данные и покажет вступительные экраны. Ваш старый сад останется в папке `Floraqua_backup`.
5. Чтобы восстановить старые данные: закройте приложение, удалите новую папку `Floraqua`, затем переименуйте `Floraqua_backup` обратно в `Floraqua`.

В текущей конфигурации папка с садом находится внутри `%APPDATA%\com.example\Floraqua\plant_garden`, а защищённые настройки — в `%APPDATA%\com.example\Floraqua`. Сброс приложения не отзывает сам ключ Gemini в Google AI Studio; он только удаляет его локальную копию.

## 4. Проверить карточки и переключение вида

1. Создайте два растения: одно с коротким именем, другое с длинным.
2. Убедитесь, что карточки сетки имеют одинаковую высоту, а кнопки **«Полить»** и **«Подробнее»** находятся на одном уровне.
3. Кнопки рядом со строкой поиска переключают **сетку** и **список**. Перейдите в другой вид и перезапустите приложение — выбор должен сохраниться.
4. Откройте подробности растения: там находятся полный уход, фото, история поливов и сезонный ориентир. Перед реальным поливом проверяйте влажность грунта — расписание остаётся подсказкой.
5. Нажмите **«Полить»**: кнопка должна коротко показать успешное действие, а дата и история полива — обновиться.

## 5. Проверить светлую и тёмную темы

Откройте **Настройки → Тема оформления**, выберите **«Тёмная»**, затем **«Светлая»** и **«Как в системе»**. Цвета интерфейса должны изменяться сразу, выбор — сохраниться после перезапуска. Если настройка **«Как в системе»** выбрана, итоговый вид зависит от темы оформления самой Windows.

## 6. Проверить время напоминаний

1. Откройте **Настройки → Время напоминания о поливе**.
2. Введите время в 24-часовом формате и нажмите **OK**. Выбранные часы и минуты должны появиться в настройках и подробностях растения.
3. Перезапустите приложение: время должно сохраниться.
4. Для проверки самого уведомления выберите ближайшее время, оставьте приложение и Windows запущенными и разрешите уведомления для приложения в настройках Windows. Показ зависит также от настроек уведомлений/режима «Не беспокоить» в самой Windows.

В настройках доступно общее время для всех растений. При изменении времени будущие напоминания перепланируются; экспорт календаря `.ics` нужно создать заново, чтобы он содержал новое время.

## 7. Что проверяется автоматически

`flutter test` включает unit- и widget-тесты сезонного интервала, данных растения, хранения сада, экспорта расписания, единой высоты карточек, списка, первого запуска, выбора палитры и анимации кнопки полива. Тесты не отправляют запрос Gemini и не требуют личного API-ключа.

Команда `flutter analyze` должна завершиться без ошибок. В этой рабочей среде исходники были подготовлены в sandbox, где Flutter SDK недоступен, поэтому окончательный запуск `flutter analyze`, `flutter test` и `flutter run` нужно выполнить командами выше на Windows или дождаться проверки GitHub Actions.

## 8. Автоматическая проверка GitHub

В `.github/workflows/flutter.yml` настроен GitHub Actions: при push/pull request он запускает `flutter analyze`, тесты и Release-сборку Windows. Для распознавания Gemini CI-ключ не нужен. После загрузки проекта в ваш GitHub откройте вкладку **Actions**, чтобы посмотреть результат сборки и тестов.
